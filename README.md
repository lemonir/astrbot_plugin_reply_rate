# 分群回复频率

_给每个群单独设定「AI 什么时候该接话」的概率插件_

</div>

---

> ## ⚠️ 装完先做两件事，否则会冲突
>
> **1. 关掉 AstrBot 自带的主动回复**
> 路径：`配置 → 平台设置 →「主动回复」`（配置项 `provider_ltm_settings.active_reply.enable`）
> 它会在同一条消息上再抽一次签，和本插件叠加后实际概率变成
> `1 - (1 - 自带概率) × (1 - 本插件概率)`，你会觉得「怎么比设置的更吵」。
>
> **2. 关掉「只 @ 机器人是否触发等待」**
> 路径：`配置 → 平台设置 →「只 @ 机器人是否触发等待」`（配置项 `platform_settings.empty_mention_waiting`）
> 它会在纯 @ 消息后开一个 60 秒等待窗口，比本插件的 `at_window_seconds` 更长，会让「15 秒」这个设置失效。
>
> 两处都在配置文件 `data/cmd_config.json` 里，改完重启 AstrBot 生效。
> 如果还装了其它「群聊接话 / 主动回复」类插件，也建议只留一套，否则会出现重复回复。

---

## 这东西解决什么问题


AstrBot 自带的主动回复只有一个全局概率，所有群共用一个值：热闹的群嫌它太吵，冷清的群又嫌它太闷。

这个插件把「要不要接话」拆成三层，并且按群独立控制：

1. **唤醒窗口** —— 被 @ 或者用唤醒前缀叫到之后，一小段时间内对方接着说的话直接接，不用抽签；
2. **概率抽签** —— 没人叫的时候，按这个群自己的概率决定要不要插一句；
3. **连击上限与冷却** —— 连着接够几句就强制闭嘴，避免两个人来回刷屏停不下来。

## 安装

在 AstrBot 插件市场搜索「分群回复频率」，或把插件目录放进 `data/plugins/astrbot_plugin_reply_rate/` 后重启 AstrBot。

- 要求 AstrBot `>= 4.10.0`
- 纯标准库实现，不需要额外安装依赖

## 配置项

全部参数都能在 WebUI 的插件配置里调，数值项带滑条。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 总开关。关掉后插件什么都不做，群里只有被 @ 或发唤醒前缀才会回复。 |
| `reply_bare_mention` | `true` | 有人只 @ 你、一个字都没写时，自己应一声。系统默认对空内容不开口，容易像没被看见。 |
| `default_probability` | `0.03` | 默认接话概率。0.03 约等于「一百句里插三句」；0 表示这个群永远不主动开口。 |
| `group_probabilities` | `[]` | 按群单独设概率，优先级高于默认值。每行一条，格式 `群号:概率`，例如 `464173145:0.1`。群号可以在群里发 `/sid` 查。 |
| `min_interval_seconds` | `30` | 抽签插完一句后，至少安静这么多秒才允许再抽，防止刷屏。 |
| `at_window_seconds` | `15` | 被 @ 或唤醒后，多少秒内对方说的话直接接、不抽签。填 `0` 关闭窗口。 |
| `window_min_interval_seconds` | `5` | 窗口内也不是每句都抢答，至少间隔这么多秒才接一次，避免同一秒挤进多条消息时连发。 |
| `combo_limit` | `7` | 最多连续接几句。到上限就清掉窗口、回到抽签冷却。填 `0` 不限制。 |
| `combo_reset_seconds` | `120` | 超过这么久没接过话，连击数自动归零，不会跨天累加。 |
| `only_when_chat` | `false` | 打开后只有纯文字消息参与抽签，图片、表情包、语音不抽。 |

## 行为说明

一次非唤醒消息的处理顺序：

```
消息进来（含 @ 或唤醒前缀？）
│
├─ 是 → 记录「这人在此刻唤醒了 Bot」，正常回复交给框架，插件不再插手
│
└─ 否 → 这个群被静音了吗？ → 是：什么都不做
        │
        └─ 否 → 是否在唤醒窗口内、且发送者就是唤醒 Bot 的那个人？
                │
                ├─ 是 → 直接接话（受窗口内最小间隔约束，计入连击）
                │
                └─ 否 → 按这个群的概率抽签
                        │
                        ├─ 抽中 → 接话（计入连击）
                        └─ 没中 → 安静
```

几个细节：

- **窗口只由 @ 或唤醒前缀开启**。插件自己接话不会刷新窗口，否则每次回复都把窗口往后推，永远停不下来。
- **窗口绑定唤醒者**。A 叫了 Bot，窗口内只接 A 的话；B 插进来照常走概率，不会白蹭。
- **连击是两种接话共用的计数**，到上限立刻清窗口并进入冷却。
- 被 @ 的那一条消息本身由 AstrBot 框架回复，不计入连击。

## 与其它主动回复机制的兼容性

⚠️ **请关闭 AstrBot 自带的主动回复**：`配置 → 平台设置 / 长期记忆 → 主动回复`（`provider_ltm_settings.active_reply`）。

它会在同样的群消息上再抽一次签，和本插件叠在一起，实际概率变成
`1 - (1 - 自带概率) × (1 - 本插件概率)`，你会觉得「怎么比设置的更吵」。

⚠️ **建议同时关闭「只 @ 机器人是否触发等待」**（`platform_settings.empty_mention_waiting`）。
它会在纯 @ 消息之后开一个 60 秒的等待窗口，比本插件的 `at_window_seconds` 更长，会让「15 秒」这个设置失效。

如果还想让 AstrBot 之外还有别的插件负责接话（比如群聊增强类插件），建议只留一套，否则会出现重复回复。

## 常见问题

**Q：设了 0 就完全不说话了吗？**
是。那个群只有被 @ 或唤醒前缀才会得到回复。

**Q：为什么刚 @ 完我，我说的话它没接？**
检查 `at_window_seconds` 是否为 0，以及是否刚触发过连击上限（到上限会清窗口冷却）。

**Q：重启后会记住连击和窗口状态吗？**
不会，状态存在内存里，重启清零。这是有意为之，重启后从头开始更稳妥。

**Q：多个群能设不同数值吗？**
可以，`group_probabilities` 里一行一个群，没配的群用 `default_probability`。
